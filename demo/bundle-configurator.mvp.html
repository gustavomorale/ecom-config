Theme sync

Importing a merchant's stylesheet is a trap — selectors collide and the next theme update breaks the widget. So the app reads computed values off real elements already on the storefront (body, headings, the add-to-cart button, links), reduces them to six numbers and strings, and feeds those back in as its own tokens. The widget keeps its own DOM and its own cascade; it just wears the store's colours, type and corner radius. Pick a storefront below and sniff it.

Why a merchant keeps paying

Drop-off analytics

The engine already emits four events — step, answer, result, addtocart. Post them to an app endpoint and every store gets a question-by-question funnel: which question loses people, which answers correlate with a bigger basket. That is the part a merchant cannot get from Shopify analytics, and it is the reason the subscription renews.

MVP model

What has to exist for this to be a public Shopify app that any store can install, and what deliberately does not exist yet.

Architecture

RuntimeThree static assets — engine, core CSS, preset CSS — identical in every store. Zero brand, product, price or copy inside them.
ConfigOne JSON document per shop in a shop-level app metafield bundle_configurator.config. 64 KB ceiling, far more than a questionnaire needs. Ships with the page cache; no extra request, no layout shift.
StorefrontTheme app extension — an app block the merchant drags into any section. Never edits theme files, so it survives theme updates and uninstalls cleanly.
AdminEmbedded Remix + Polaris. Opens on the category step — what is this configurator for — which seeds a working template, then four editing screens: Questions, Bundles, Add-on rules, Appearance. Forms over the arrays, not a code editor.
CategoriesA registry of starting templates. Two are full questionnaires; the rest are generated from a terse spec so each still ships as a working configurator with three questions, three tiers and real add-on rules. Adding a category is adding one object to the list — nothing else in the app knows the set.
BrandNothing is stamped. brand.id, brand.name and the footer are empty by default and the footer renders only when a merchant fills them. No illustration colour, product name, price or copy ships in the runtime.
Theme syncRuns at boot on the storefront, caches the derived tokens in the metafield, re-sniffs when the merchant asks. Merchant overrides always win.
Cartpermalink by default — works on every theme and every checkout with no JS API. ajax when line-item properties or selling plans are needed.
SafetyConfig arrives from merchant input, so rule expressions are token-whitelisted before compilation. Only numbers, known field names, arithmetic and min max round floor ceil abs. Anything else is rejected and logged, never executed.

Scope

v1 — shipApp block, config metafield, the category step and its templates, the four admin screens, permalink cart, glass + base presets, theme sync.
v1.1Analytics endpoint and the funnel above. Ajax cart. Answer persistence via sessionStorage and a resumable link.
v1.2Price sync from the Storefront API, so the preview total can never drift from checkout. Metaobject-backed accessory catalogue.
v2Draft orders for high-value configurations. Per-market and per-locale configs. Merchant-defined scenes.
Not in v1Multi-language (one config, one locale). Customer accounts. B2B price lists. Anything requiring an app database.

Must fix before a public listing

AccessibilityBlocking. Options are divs with click handlers. They need real button / radio semantics, keyboard navigation, focus management and visible focus rings. Shopify's app review checks this, and glass surfaces make contrast harder, not easier — every token pair needs a 4.5:1 audit.
Price driftPrices live in both the config and Shopify. The displayed total is a preview; checkout is the source of truth. Say so in the UI until Storefront API sync lands.
PersistenceAnswers are lost on refresh. Cheap to fix, disproportionately annoying.
Performancebackdrop-filter on many stacked layers is expensive on low-end Android. The preset degrades to opaque surfaces where the property is unsupported, but it should also degrade under prefers-reduced-transparency and on a measured slow device.
Sniffer failureTheme sync guesses. It needs a confidence signal and a one-click "ignore, use my colours" in the admin, or it will feel broken on the themes it reads wrong.

Commercials

PricingUsage-independent monthly tiers by questionnaire count and step count. A configurator is a conversion tool — per-order pricing is harder to explain and punishes success.
Scopesread_products for the resource picker, write_app_metafields for the config. No theme write scope — app blocks do not modify the theme.
OnboardingNever an empty questionnaire. The category step seeds a working template, theme sync runs on install, and the merchant's first screen already looks like their store with real questions in it.
ProofThe funnel is the retention mechanic. A merchant who can see that question 3 loses 40% of shoppers has a reason to open the app next month.
